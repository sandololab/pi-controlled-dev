# Greenfield Project Bootstrap

The current `/controlled-dev` entry and its `project new` alias work in the current directory through `CurrentProject` and native Project Planning. The separate location-selection wizard has been retired. This document describes the retained bootstrap engine and its historical artifacts; see [the current manual](../USER-MANUAL.md) for the user flow.

Project-level Proposal, Intent and Result artifacts reuse DurableStore canonical immutable artifacts and its atomic CAS index. No task state, transition, task ledger, second WAL, planner, memory lifecycle or Git executor is introduced. The frozen workflow remains 11/43.

The read-only pre-task Scout has an additional analytical proposal format and one package skill. It reads installed guidance before a target exists, then the existing Project Planning path reads the initialized project and native memory. Technical choices are native repository-scoped ProjectMemoryProposal values, never lessons, source claims or implicit binding decisions. The model wire schema derives closed per-kind content variants from the existing memory wire fragments, matching the native validators; a convention cannot contain ADR or constraint fields. Unexpected fields are rejected, never silently removed. Natural-language corrections create another exact draft. The former bootstrap wizard handled clarification panels and explicit creation approval. Current Project Planning persists unanswered questions and human replies across cancellation/reopen, keeps proposal correction separate from plan approval, and never treats a clarification as permission to start Developer. Reversible application details are proposed for review rather than blocking the empty Git baseline.

A bootstrap confirmation binds target anchor/leaf, expected directory identity, objective, preferences, initial branch, empty-root strategy and all initial technical choices. The native process-local request/receipt is consumed under the existing workspace lease; copied JSON cannot initiate effects. Intent and approval evidence are indexed before mkdir or Git initialization. Cancellation performs no target or project-store mutation.

Host Git initialization is a bounded CandidateGit method using the existing private allowlist executor, sanitized environment, noninteractive settings, configured identity and hook/signing policy. An empty template prevents copied global hooks. An exclusive Git-directory reservation prevents two profiles from reinitializing the same target. No files are imported, application files written, dependencies installed or remotes configured. The empty index supports ordinary first-task promotion without a special merge workflow.

Supported inputs are an absent final leaf with an existing canonical parent, or a completely empty directory. Existing repositories with commits redirect; pre-existing unborn repositories are explicitly unsupported. Nested Git, symlinks, traversal and control-plane locations fail closed. Directory identity and contents are rechecked after approval and before each effect.

A portable project identity is bound to the initial empty root commit message and a bounded technical marker in Git metadata. Legacy projects without the marker retain the existing path-derived identity. Memory, planning, task storage, promotion and checkpoints share projectIdentity; workspace locks remain keyed to the current canonical path. Moving a complete initialized directory preserves native project records in the same external profile. Active task path migration is not provided.

Recovery reads the exact indexed intent and receipt, reclaims only an exact verifiably dead host lease using LockManager's existing generation-claim guard, and reconciles bounded effect proofs. Intent-only, created empty directory, initialized unborn Git and exact existing root commit are supported. The commit object is recorded before its branch update; known Git update surfaces are checked separately. Proof gaps, extra files, unexpected metadata/branches/commits or uncertain process ownership remain blocked. No rollback, directory removal or reset is attempted.

The result index retains native Project Goal/Project Memory/Project Plan references in a setup artifact, without copying their semantic contents or granting additional authority. Initial records remain PROPOSED until the existing individual native confirmations. Project Plan DRAFT, review, correction and approval use ProjectPlanningRepository and PreTaskScout.plan. The plan review panel displays the current official project directory; leaving the panel retains a saved draft and shows that directory and draft status in a host-authored notification. The machine-local directory is display context only, not persisted in portable plan artifacts. Neither bootstrap nor an unapproved planning draft starts Developer. A later selected PlannedTask uses the normal TaskSpec wizard and ControlledTask.

Project.md is a derived human projection of initial state, goal, accepted memory and current plan with relative wiki links. Markdown edits cannot initialize Git or approve anything. Tests use real Git and separate concurrency/crash workers, with explicitly declared UI/provider doubles. End-to-end verification continues through two native planned tasks, isolated Developer candidates, independent Reviewer, validation, human-approved promotion and existing Integration Checkpoints. A real-human TUI check and real-model check are distinct evidence.
